Authentication errors are silently ignored during account updates

When account_management returns an authentication error, the agent continues without recovering or telling the user that the request failed.

What Engine observed

The behavior claim to verify before deciding what to do.

Expected

The agent refreshes authentication and retries, or clearly tells the user that the account update could not be completed.

Observed

The tool returns 401 Unauthorized. The agent does not retry and responds as though the update succeeded.

User consequence

Users may believe an account change was completed when no change was made.

Why this matters

Impact is separate from how frequently the pattern occurs.

The failure changes the user-visible outcome. The error is not only an internal tool failure: the agent gives a misleading confirmation and the requested account update remains incomplete.

        What differs in similar cases that succeed?
