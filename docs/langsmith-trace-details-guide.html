LangSmith observability reference

How to read a LangSmith trace

A trace is not one generic stack of “agent steps.” Its run types determine how LangSmith renders each operation, while Messages and Details answer different debugging questions.

The observability hierarchy

Thread

A multi-turn session. Traces join a thread when they share thread_id.

Trace

All runs created by one operation or turn. The trace ID equals its root run ID.

Run / span

One unit of work: a model call, tool invocation, retrieval, prompt render, parser, or chain.

Messages and Details are complementary

Use Messages to orient in the conversation. Use Details to inspect a selected run.

Messages · trajectory view

“What did the agent do and say?”

  • Flattens nested runs into an ordered conversation.
  • Shows AI responses, grouped tool calls and tool results, thoughts, and subagent actions.
  • Requires compatible message data; thread behavior also depends on thread_id and agent metadata.

Details · run inspector

“What happened inside this exact run?”

  • Preserves the nested trace tree and currently selected run.
  • Shows feedback, typed input, output, errors, timing, tokens, cost, and attributes.
  • The right side changes when a different run is selected.

Run types in the trace tree

These types come from the run’s run_type. LangSmith uses them for icons and specialized rendering.

Root

The top-level run for a trace. “Root” is a tree position, not a separate official run_type.

chain

A sequence, graph node, routing step, or composition of operations.

llm

A model call. Details can show messages, first-token time, tokens, model, and cost.

tool

A function or external action selected by the model. Tool messages auto-expand in Details.

prompt

A prompt template formatting inputs before a model call.

retriever

A document lookup. Properly formatted outputs render documents and metadata inline.

parser

Transforms raw model or retrieval output into structured data.

RunnableSequence

A LangChain visual subtype of chain: steps execute in sequence.

RunnableParallel

A LangChain visual subtype of chain: branches can execute concurrently.

embedding

An embedding API call. LangSmith currently displays it with the chain icon.

Message roles

Message roles describe conversation content inside LLM inputs/outputs and the Messages trajectory. They are different from run types.

Human / User

The end user’s request or follow-up.

AI

Model text, tool calls, structured response content, and associated model metadata.

System

High-priority behavior and policy instructions sent to the model.

Tool

The result paired to a model tool call, usually by tool-call ID.

Function

A legacy or provider-specific function-call message. Modern tool calling usually uses Tool.

Unknown

Fallback rendering when LangSmith cannot map a message to a recognized role.

Additional Fields

Provider-specific or structured fields that are not the primary visible message content.

Reasoning / Thought

Extended-thinking content shown inline and collapsed by default when available.

Realistic trace shapes vary by issue

Silent authentication failure

Failure lives in a state-changing tool and its shared HTTP client; the final model compounds it by claiming success.

agent → ToolNode → account tool → HTTP 401/403 → route_after_tool → LLM

Unsupported claim

The retriever succeeds. The failure is the mismatch between retrieved evidence and the final LLM output.

prompt → retriever → parser → grounded_answer → LLM

Agent loop

Individual tool calls can succeed while the trajectory is inefficient because state and arguments do not change.

agent_loop → LLM → ToolNode → repeated tool → loop_guard

Latency and cost

No functional error is required. Critical-path spans, token accumulation, and parallelism reveal the issue.

parallel retrieval → context assembly → slow high-token LLM

Prompt regression

The prompt version and route explain why required clarification steps disappeared.

prompt v43 → intake → route → agent → premature diagnosis

Wrong destructive tool

The mutation succeeds technically. The problem is intent classification and a skipped confirmation gate.

tool schema → classify → agent → destructive tool → missing gate

Guardrail fail-open

An unavailable policy decision should deny access, but routing leaves protected tools callable.

authorization → policy timeout → fail-open route → protected tool → LLM
