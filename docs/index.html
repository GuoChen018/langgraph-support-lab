What we did, how it connects, what LangSmith should become

Field notes from building a LangGraph developer-support agent and running it through LangSmith’s trace → dataset → evaluate → experiment loop — written so you can explain the system and form a senior design opinion under pressure.

Agent LangGraph support lab Dataset support-agent-baseline-v1 Loop build → trace → eval → improve

One-sentence summary

We built an imperfect support agent, saved useful test questions with examples of the expected behavior, scored agent versions with evaluators, fixed false-high confidence, and proved the fix in a second experiment — while discovering that Playground experiments test prompts, not our graph.

Glossary

Workflows

1
Save test questions and define the expected behavior
For each question, describe what a good response should do. Do not automatically treat the agent’s last reply as correct.
2
Attach evaluators
LLM-as-judge for message quality; code checks for clarify / confidence.
3
Run baseline via SDK
evaluate(target) invokes your LangGraph agent over every example.
4
Change the agent
We fixed confidence to use evidence relevance instead of source-type count.
5
Re-experiment & compare
python scripts/run_experiment.py --prefix improved-confidence
Interesting / failed trace
  → Add to dataset          (save the question as a test case)
  → Edit reference output   (describe the expected response)
  → Optional annotation     (ask another person to review it)

Trap: LangSmith may prefill reference with the agent reply.
That is only a draft. Review it before treating it as the expected answer.
Same dataset + evaluator
  → Playground prompt + model (e.g. Claude)
  → Experiment named pg::claude-sonnet-5::…
  → Scores the prompt — not your LangGraph agent

Use it to learn the product. Don’t confuse it with agent truth.
